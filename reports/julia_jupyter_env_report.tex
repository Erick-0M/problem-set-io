\section*{Decision}
Docker, inside the existing project container (\texttt{opt}), is the primary interface: it follows the
repo rule of a single container, serves JupyterLab at \texttt{localhost:8896}, and is reproducible.
The base image only ships Julia 1.9, so \texttt{code/Dockerfile} now installs Julia 1.12.5 (official
tarball, architecture-aware) with its depot in \texttt{/opt/julia\_depot}, plus IJulia.
Packages live in a project-local environment, \texttt{code/scripts/julia/} (\texttt{Project.toml},
\texttt{Manifest.toml}), selected by the kernel \texttt{julia-project} (``Julia 1.12 (project)'').

\section*{Verification}
The image builds; \texttt{jupyter kernelspec list} shows \texttt{julia-project}; a notebook executed
headlessly with that kernel reports Julia 1.12.5 with active project
\texttt{/home/repo-intro/scripts/julia/Project.toml}; \texttt{Pkg.add("DataFrames")} installed and loaded
(test change reverted, so the committed environment is empty).

\section*{Native alternative}
juliaup (Julia 1.12.5 already installed on the host) with VS Code's Julia extension is the best native
interface; the same \texttt{Manifest.toml} is used. Details in \texttt{code/scripts/julia/README.md}
and the repository \texttt{README.md}.
